数据快照：2026-10-14 · 深入分析：2026-10-27 · 215 个模型 · 93,359 个目标构件

数量有一定参考价值，但不能直接代表内容质量。模型之间确实存在显著差异；其中一部分差异来自字段写法、属性组和模板内容，而不只是物理构件的细节多少。

本页集中回答两个问题：每个构件“16 个属性”里包括什么？合计“4,688 种字段”为什么不能说明每个模型都很丰富？全部图表基于已有审计数据重新计算，没有修改模型或重新生成 embedding。

一、16 → 12 是计数规则改变，不是“四分之一的信息无效”

把一个构件的属性集展开后，每个带值的末级字段算一项。例如 Pset_WallCommon.IsExternal=true 算一项。全部构件共有 2,000,878 次非空字段出现；同一个字段出现在 100 面墙上，就在这里计 100 次。

读图：每条横条是一类构件的平均字段数。各色部分可以相加，所以这里使用平均数；中位数不能按这种方式拆分相加。蓝色只是“按规则保留”，不是“已经确认独立、正确、有用”。

例如同一构件 3 个 Reference 都填了同一个类型名，只去掉多出的 2 份，同时保留名称和首个引用，再去明确占位：中位数变成 14，而不是 12。全部字段出现次数仅减少 7.74%。这是一项敏感性检查，不是建议直接修改现有提取结果。

16、14、12 各是对应规则下全部构件计数的中位数。不能用 (16−12)/16 推算全部数据中无效字段的比例，也不能理解为每个构件都减少了 4 项。

为什么保留的字段数仍会高估内容细节？

真实案例：model_217 的一面墙（node 1）。它有 62 个非空字段，按原规则剩 59 个；这 59 个里，31 个值只是字段名本身，例如 Manufacturer="Manufacturer"、WarrantyStartDate="WarrantyStartDate"、NominalHeight="NominalHeight"。字段名看起来覆盖厂家、保修、尺寸，但这些值并没有提供具体厂家、日期或尺寸。

“值等于字段名”是模板内容的检查信号，尚未对全部模型做这种内容质量审计。不能把所有这种值自动判无效，也不能据此给整个数据集计算可靠的“有效信息量”。

相同值也不一定重复：IsExternal=false 与 LoadBearing=false 分别表达“非外部构件”和“非承重”，两个 false 都有意义。多个构件共用同一材料或类型也很正常。当前去重只针对同一构件内、值相同的 Reference 额外副本。

二、只比较同一种构件，模型间差异仍然很大

不能直接拿“一个门窗多的模型”和“一个梁柱多的模型”比较总属性数。这里先在每个模型内，只看同一类构件，取它们字段数量的中位数，作为该模型这类构件的典型数量；然后比较模型之间的差异。每个模型权重一样。

读图：以墙为例，把 215 个模型各自的典型字段数量从少到多排列，去掉两端各约 10% 后，中间约 80% 模型落在 4–40 个字段。深色带为中央一半模型的范围，橙色点为模型典型数量再取一次中位数。这里不是说 80% 的墙都落在这个区间。

所以差异不只是构件种类比例造成的。排除字段特别多的 model_6 后，墙的对应范围仍约 4–39.7，说明也不是仅靠一个极端模型撑出的现象。板的区间端点 3.7 来自百分位插值，并不表示一个构件有 3.7 个字段。

“常见字段”只是一个便于比较的筛选：该类全部构件中至少一半有值，而且含该类构件的模型中至少一半出现过该字段。50% 是本次筛选线，不是行业标准。计数仍按完整字段名，未全面合并同义字段，也未额外删除所有占位或模板内容，因此不是可靠的任务特征清单。

这意味着什么？

同样叫“墙”或“门”，不同模型可能提供不同种类和数量的输入。对后续分类或检索任务，既需要检查丰富模型是否只是多了软件、族参数和模板文字，也需要检查精简模型是否缺少任务必需的尺寸、材料和性能。当前统计不能直接证明 embedding 好坏，也不能推断某一种软件更好。

三、4,688 个字段名，有超过一半只来自一个模型

model_6 只有 1,021 个构件，占 1.09%，却贡献了 2,720 个只在它出现的完整字段名，占全部 4,688 个字段名的 58.02%。作为敏感性检查，排除它后，其他 214 个模型合计出现 1,968 个完整字段名。

真实例子：324 个字段的一扇门

已发布案例中的 model_6 门 node 665 有 324 个字段：268 个来自门族属性组 AC_Equantity_Door_26，46 个来自 ArchiCADQuantities，其余 10 个来自基础字段、公共属性和标准工程量。它有许多不同侧面、不同标高基准、二维/三维口径的参数，不能把 324 直接理解为 324 个独立性能维度。

这些详细参数可能有价值；稀有本身不代表无用。另一方面，ArchiCADQuantities.W/D Opening Width on the Reveal Side 与其他侧面或名义宽度字段即使同为 900，也不能只因数值相同就合并，它们的口径可能不同。

结论：大量字段代表了多套属性命名和参数体系的并集。需要先核对同义关系、用途、值与单位，再评价它们是否增加了任务需要的细节。不能把“只在一模型出现”一律当作其他模型缺失。

四、构件中常见，与模型中通用，是两件事

一个直接的例子：墙宽度字段 BaseQuantities.Width 出现在 9,564 / 28,313 面墙（33.78%）上，但只来自 10 / 215 个模型（4.65%）。几个构件数量较多的模型，就能把前一个比例抬高。因此不能把“约三分之一的墙有值”理解成“约三分之一的模型通用”。

另一个宽度字段 Qto_WallBaseQuantities.Width 在不同路径下统计。目前没有把这些潜在同义写法全面合并。某一条路径没有值，不等于这个构件完全没有宽度信息；也不能把两条覆盖率简单相加，因为可能存在重叠或不同物理口径。

选择用于训练或比较的稳定属性时，应同时看：有多少构件提供它、有多少模型提供它、不同模型是否用另一种写法表达它，以及实际值是否可靠。

现在可以下什么结论，下一步如何验证？

  1. 有些文本重复，但不能据此说大部分字段无用。相同 Reference 的额外副本占全部字段出现次数的 6.04%；只去这些副本与明确占位，减少 7.74%。名称、第一份引用、0 和 false 都可能有用。
  2. 模型之间的输入差异确实值得单独处理。这种差异在控制构件类别后仍存在；字段词表又明显受一个特殊模型影响。后续应分别报告各模型、各构件类别、排除特殊模型后的结果。
  3. 要判断“够不够细”，需要针对任务定义信息项。例如墙是否需要厚度、材料层、承重、防火、热工信息；不能仅凭字段总数评价。需在补齐提取、统一同义字段和单位后，检查这些信息项是否有真实值。
  4. 要判断这些差异是否影响训练，需要做消融实验。可比较原始文本、只去重复引用与占位、规范同义属性后的表现，并按模型分组划分数据，避免同一模型的模板同时出现在训练和测试中。当前描述统计没有验证准确率或泛化效果。
