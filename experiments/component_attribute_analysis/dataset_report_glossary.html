先记住：“字段”是一种记录项，例如“是否承重”；“值”是填写的内容，例如 true。“对象”或“节点”在这里都指一个进入实验图的构件。多数百分比都在回答：100 个构件或 100 个模型里，有多少个具备这项记录。

各种覆盖率怎么计算

原来的名称直白解释例子与注意点
对象覆盖率这一类构件中，有多少比例填写了某个属性。100 面墙，80 面有承重属性，就是 80%。分母是墙的数量，不是所有类别的构件数量。
模型覆盖率包含这类构件的模型中，有多少模型至少有一个构件填写了这个属性。10 个有墙的模型，6 个模型里找到过耐火等级，就是 60%。每个模型只出现一次，也算该模型有这个字段。
模型等权平均覆盖率先算每个模型内部填写这个属性的构件比例，再平均。大、小模型各占同样权重。A 模型有 900 面墙、全部填写；B 模型有 100 面墙、全部没填。对象覆盖率是 900/1000=90%；模型覆盖率是 1/2=50%；模型等权平均覆盖率是 (100%+0%)/2=50%。三者回答不同问题。
工程量覆盖率至少填写了一项工程量集属性的构件比例，例如长度、面积、体积或周长。100 面墙，70 面在 Qto_ 或 BaseQuantities 属性组里至少有一项非空值，就记为 70%。只填写面积也算，不要求长宽高、面积、体积全部齐全。其他自定义组里的数量信息未计入这个指标。
Material 字段覆盖率当前属性表里，Material 这一列有值的构件比例。100 扇窗，Material 一列只有 2 扇填写，就是 2%。部分其他窗可能在软件自定义属性集中有材料文字，因此该比例不能代表所有属性中材料信息的总覆盖。
材料类属性至少一项归为“材料与构造”的任意字段有值的构件比例，比只检查 Material 一列范围更宽。Material 为空，但 Materials and Finishes 中有门框材料，也可能计入。分类按字段名称规则判断，还包括部分构造字段。
内容类型表中的百分比某类构件至少具备一个相应内容字段的比例。“尺寸与工程量 90%”表示 100 个构件中约 90 个至少有一个相关字段，不表示这些构件的尺寸信息已经 90% 完整。

“同时满足 50% 对象/模型覆盖的字段数”是什么

对每个字段分别检查两条：至少一半的该类构件填写了它；至少一半的含该类构件的模型中出现过它。两条都满足，才把这个字段计入一次，最后统计有多少个字段通过。50% 是本次分析选用的筛选线，不是 IFC 标准，也不是质量合格线。

例如一共 100 面墙、分布在 10 个模型中：

示例字段有值的墙出现过的模型是否计入字段数
承重80/100 = 80%8/10 = 80%计入，两条都通过
某项热工参数80/100 = 80%2/10 = 20%不计入，集中在两个大模型
某项细部参数20/100 = 20%8/10 = 80%不计入，虽分布广，但实际填写的构件少

这三个示例字段最终只有 1 个通过，所以“字段数”是 1。这个数字描述字段是否经常能获得，不能证明字段有用或内容正确；Name、重复 Reference 和 NOTDEFINED 仍可能通过。

属性数量和其他计数怎么读

名称含义
非空属性数一个构件实际填写了多少个末级字段。空白、None、空容器等不算；0 与 false 是有效值；NOTDEFINED 算非空，但说明内容没有明确给出。
P10 / 中位数 / P90把构件按属性数量从少到多排序，分别取约 10%、50%、90% 位置上的数量。P10–P90 是中间约 80% 的范围，不是最少与最多值。并列和分位数插值可能产生小数。
剩余属性数对每个构件去掉 Name、所有末级名为 Reference 的字段，以及 NOTDEFINED/UNKNOWN 等占位值后，再数还有多少字段。其他重复信息仍可能保留，不能当作“独立有效信息量”。这只是统计口径，不等于建议把所有名称和引用删除。
不同值数某个字段填写了多少种不同内容。例如“是否承重”只出现 true 和 false，通常是 2 种。数值沿用源单位，跨模型不同值数不直接代表不同的物理规格。
重复引用节点比例有两个或更多 Reference 字段填写相同内容的构件占比。每个构件最多计入一次；一面墙重复很多次，也只算一个受影响构件。
去 Name 后组合数去掉 Name 后，还能区分出多少套完整的字段和值。其余字段缺失差异也参与比较。53 面墙得到 5 种组合，表示当前属性把它们描述成 5 套记录；它们的几何和位置仍可能不同。
稀有字段 / 字段长尾仅在很少构件或模型中出现的字段。全数据集列名很多，但大多数构件并不具有这些列中的实际值。
数据类型文本是名称和说明等字符串；数值是尺寸、数量等数字；布尔值是 true/false。0 和 false 不等于没填。数据类型不是构件类别，也不说明该值准确。

两张图各在回答什么

左图：一个构件通常填写多少项属性，差异有多大？横轴是属性数量；浅色粗线是 P10–P90；实心点是全部非空字段数的中位数；空心点是按上述规则删除名称、引用、占位值后，剩余数量的中位数。标出的数字属于实心点。墙的实心点是 17、空心点是 13；每面墙减少的数量可以不同。

左图说明：属性量分布较宽，名称、引用和占位值确实占据部分记录；仅凭数量不能断定内容足够细。

右图：原始 IFC 中有材料名称的构件，有多少被写进了当前 Material 一列？浅色条检查原始 IFC，包括材料集合内部的名称；深色条只检查当前属性表的 Material 一列。两边都针对同一批进入实验图的构件。

右图中窗的浅色约 93.6%、深色约 1.3%，说明源文件大多能找到材料名称，而当前 Material 一列保留很少。其他自定义字段中可能仍有材料文字。空间没有实体材料通常合理，不能按这个比例判为空间数据质量差。

“原始 IFC 遗漏对照”各列怎么读

这里的“源文件”是转换前的 .ifc 文件，“当前”是转换后的属性文本，尚未重新计算 embedding。“有值”只表示非空，不保证正确，也不保证源值与当前值一致。

列名含义
原始属性名 / 来源检查的是哪个字段，以及原始 IFC 把它存在哪里：实例 Pset/Qto 是挂在具体构件上的属性或工程量；类型继承 Pset/Qto 是由类型统一共享的属性（也包括部分类型专用定义）；材料定义/材料组成集是材料关联；空间关系是楼层或空间容器关联。同一字段在不同构件中可能有不同来源。
源 IFC 有值的构件数原始 IFC 中能读取到该字段非空值的构件数量。
当前有值的构件数在上述源文件有值的构件中，当前对应字段仍有非空值的数量。Material.Name 对照 Material；部分 Type 字段对照相应实例字段。
当前缺失的构件数源有值、当前对应字段为空或不存在的构件数。等于前两列相减。只说明明确字段缺少，含义有时仍部分存在于 Name 等其他文本里。
其中来自类型的遗漏数上述缺失中，原始值位于类型共享属性里的构件数量。这是全部缺失的一部分，不要再加到缺失总数上。
值不同的构件数源和当前字段都非空，但内容不同的构件数量。数值允许已有提取器的三位小数舍入误差；不同不一定全是错误，还可能需要检查类型与实例的覆盖规则。
源中有该字段的模型数至少有一个构件在原始 IFC 中具备该字段非空值的模型数量。
发生遗漏的模型数至少有一个构件漏掉这个字段的模型数量。一个模型可能有些构件保留、有些遗漏，不表示整个模型全部丢失。
源值示例给出原始值、所在模型和这个值在该模型出现的次数，不是跨模型平均值。物理量需要结合源单位理解。
原始文件包含材料层的构件数有材料层定义的构件数量。不是材料层的总层数；一面墙有三层材料，这一列仍计一个构件。

用墙的传热系数读一行：源中 12,189 面墙有值，当前 4,359 面有值，差额 7,830 面在当前缺失；这 7,830 面的遗漏都来自类型共享属性。原始有值的模型为 114 个，其中 109 个至少发生过一次遗漏。它只评价“传热系数”这一项，不能据此判断整面墙所有 semantic 都丢失。
