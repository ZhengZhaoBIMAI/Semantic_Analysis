哪些信息真的进入了属性文本

当前 CSV 的钢筋间距和环境影响属性集只有 Reference，没有相应的钢筋间距或环境指标数值。名称中的规格不等于已提取、带单位的数值属性。

“进入”指按当前代码重建的 embedding 输入文本。向量不是属性字典，不能保证每个字段都被无损编码。原有属性向量若曾复用，其历史完整输入无法仅凭向量确认。

统计口径与改进建议


统计口径
    

  • 样本是 Stage1 图中的目标节点，不是原始 IFC 中所有建筑对象。以 node_index.csv 的 node_type 分类，并核对 GUID 和节点编号。IfcWallStandardCase 等映射以图节点类别为准。
    • 

  • 属性输入由 semantics_Embed.py 的 drop_ignored_property_columns 与 combine_properties 原样重建；逐层展开 Pset / Qto JSON 统计，不把整个属性集算作一个细节。
    • 

  • 覆盖率 = 本类该属性有实际值的构件数 / 本类节点总数。None、空字符串、NaN、空容器不算实际值；false 和 0 是有效值。NOTDEFINED 为非空占位值，明细会保留，需结合含义判断其信息量。
    • 

  • 按当前默认阈值检查输入长度，并核对已有 semantic_embedding 的 1007 维、7 维 one-hot、GUID 对齐和有限数值。未重新调用 embedding API，未改动模型数据或训练配置。
    • 

  • 原始 IFC 对照包含实例基础属性、实例与类型继承属性、部分类型定义、材料定义和空间容器信息，不覆盖 IFC 几何表示内部的全部参数或所有关系。
    • 

  • 这是一个模型的案例分析。它适合定位当前提取链的具体遗漏，不能据此断言其他模型具有相同覆盖率。


建议的改进顺序
    

  1. 补齐类型继承与专用定义。 合并实例和类型的属性，实例值优先。门扇等 IfcDoorPanelProperties 也应规范化，避免把实例名变成大量不同的字段。保留来源，记录重名冲突。
    2. 

  2. 去重和规范命名。 对重复 Reference 去重。拆分 Family / Type / 实例编号，做去掉 Name 编号的消融实验；不直接删除具有实际类别或规格含义的名称。
    3. 

  3. 按任务补充显式数值。 墙厚、板厚、截面宽高、工程量等需要源文件支持或几何计算，并记录单位和来源。名称中的 “100mm” 可以作为线索，不能当作已提取且验证的数值字段。
    4. 

  4. 保留结构化属性通道。 对尺寸、承重、外部性、耐火等级等关键字段保留可解释的数值/类别特征，与文本 embedding 对照消融。维度增加本身不意味着信息增加。
    5. 

  5. 扩展到多模型复核。 在不同导出软件和不同模型上核对覆盖率、类型继承收益、跨模型同义字段和单位一致性，再判断哪些属性可作为稳定特征。
